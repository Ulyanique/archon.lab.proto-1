# assets — медиа

Визуальный архив сайта: `concept-art/catalog.json`, файлы изображений для сайта — `public/images/`. Для каждой работы указываются описание, авторство, условия использования и точный промпт; изображения не утверждают факты канона.

## Что и где хранить

| Тип | Каталог (создаётся при первом файле) | Хранение |
|---|---|---|
| Изображения, концепт-арт, карты, референсы | `images/`, `concept-art/`, `maps/`, `references/` | обычный git, если файл небольшой |
| Аудио, видео, 3D-модели, исходники (`*.psd`, `*.blend`, `*.kra`) | `audio/`, `video/`, `models/` | **Git LFS** (правила уже в `.gitattributes`) либо внешнее хранилище со стабильной ссылкой |

Включение LFS (один раз на клон): `git lfs install`. Без LFS тяжёлые файлы не коммитить.

## Метаданные и проверка

Для каждого файла: название · описание · авторство · источник · **лицензия** · связанные сущности (ID) · тип материала. Материалы с неизвестными правами не используются как собственные и не коммитятся.

## Ссылки

Вики-ссылка `![[имя.png]]` разрешается по имени файла среди не-markdown файлов репозитория; `lore validate` сообщает о битых вложениях. Имена файлов должны оставаться стабильными.

## Медиа на страницах записей

Для изображений добавьте запись в `concept-art/catalog.json`: уникальный `art-NNN`, локальный файл в `public/images/`, `alt`, автора, условия использования, точный промпт и массив `related` с ID опубликованных сущностей. `width` и `height` рекомендуются для правильных пропорций и предотвращения сдвигов. Указатель выводит работу на каждой указанной странице; он не утверждает облик или факт в каноне. Не добавляйте непубличные ID. Небольшие webp-файлы предпочтительны для скорости.

Для самостоятельной модели GLB добавьте файл в `public/media/` и запись в `media/models.json`: `id` вида `model-001`, `title`, `description`, `file` вида `/media/name.glb`, `author`, `rights`, `related` (массив ID). Каталог сейчас пуст: модель появится только после добавления реального файла. Сайт предлагает скачать GLB, встроенного 3D-просмотрщика пока нет. Крупные файлы храните по правилам проекта через LFS или отдельно согласованное хранилище; данный каталог принимает только локальные файлы. Проверяйте права и происхождение, не публикуйте материалы с неизвестным разрешением.

Изображения на странице связанной сущности и в каталоге можно открыть в крупном просмотре. В нём повторяются статус визуального исследования, описание, авторство и условия использования, есть переход к промпту и ссылка на оригинал. Просмотр закрывается кнопкой или клавишей Escape.

### Проверка перед публикацией

Запустите `npx tsx scripts/lore.ts validate --strict`: она проверяет схемы каталогов изображений и моделей, уникальность их ID, наличие локальных файлов внутри `public`, незагруженные указатели Git LFS и связи только с опубликованными сущностями. Для атмосферного изображения допустим пустой `related`; для модели нужна хотя бы одна связь. Ошибки также попадают в отчёт `lore.ts report`. Проверка не определяет подлинность авторства, юридическую действительность прав, корректность содержимого изображения или GLB; это нужно проверить отдельно. Workflow в `.github/workflows-updates/` GitHub Actions автоматически не запускает.
