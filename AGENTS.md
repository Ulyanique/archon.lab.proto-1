# AGENTS.md — правила работы над Archon Universe

Файл обязателен к прочтению для **любого** AI-агента (и человека) перед любой правкой. Он не привязан к поставщику моделей: подходит для OpenRouter, Ollama, локальных и облачных моделей, любых OpenAI-compatible API и CLI-агентов.

## 0. Золотые правила

1. **Источник истины — `universe/`** (Markdown + YAML). Не создавай копий лора в коде, JSON, БД, сайте или игре.
2. **Не выдумывай канон.** Нет сведений → пиши `—` и добавляй пункт в «Противоречия и неизвестные сведения» или в [`Открытые вопросы`](universe/00-meta/Открытые%20вопросы.md). Не заполняй пустые разделы «для красоты».
3. **Не утверждай канон сам.** Статус `canon` ставит только человек-владелец. Агент максимум предлагает `proposed`/`review`.
4. **Новые идеи — в `drafts/`**, не в `universe/`.
5. **Не удаляй и не переписывай** чужое целиком. Делай локальные правки; удаление — только по согласованию (вместо удаления — `deprecated`/`archived`).
6. **Гипотеза ≠ факт.** Любое «предположительно/возможно» из источника остаётся оговоркой и не превращается в утверждение.
7. **Не меняй художественный стиль** (визуальный, звуковой) без согласования.
8. **Не смешивай лор и игровые механики.** Характеристики, баланс, классы — в Game Data, не в статьях.
9. **Не создавай технологии, локации, персонажей** только чтобы заполнить пустой раздел.
10. **Научная достоверность:** никакой магии и произвольных нарушений физики. Необъяснимое помечай как неизвестное (`science_status: unexplained`).

## 1. Перед созданием/изменением сущности

1. Прочитай [`Правила канона`](universe/00-meta/Правила%20канона.md) и [`docs/worldbuilding/ENTITY-GUIDE.md`](docs/worldbuilding/ENTITY-GUIDE.md).
2. **Найди дубликаты**: поиск по `id`, `title`, `aliases` (`grep -ri "<имя>" universe drafts`; `npx tsx scripts/lore.ts index` → `build/lore/index.json`).
3. Проверь связанные сущности и их статусы; отметь противоречия.
4. **Сохраняй ID.** ID постоянен: не переименовывай, даже если меняется название или файл.
5. Бери шаблон из `templates/`. Даты `created`/`updated` — сегодняшние (`YYYY-MM-DD`).
6. Укажи источник в разделе «Источники».

## 2. Перед коммитом (обязательно)

```bash
npx tsx scripts/lore.ts validate   # 0 ошибок обязательно
npx tsx scripts/lore.ts report     # посмотри новые противоречия
npx vitest run
npx tsc --noEmit
```

Автоматические проверки **никогда** не изменяют канон. Не «чини» валидатор, подгоняя данные под него, и не ослабляй проверки ради зелёного CI.

## 3. Процесс изменений

Задача → изучение существующих материалов → план → **черновик** (`drafts/`) → проверка другим агентом (Continuity Auditor) → проверка человеком → Pull Request → утверждение → слияние.

- Крупные изменения — только в отдельной Git-ветке (`lore/<тема>`, `feat/<тема>`, `fix/<тема>`).
- Агент **не сливает** спорные изменения в канон и не мержит собственные PR, затрагивающие `universe/`.
- Изменения канона записываются в `CHANGELOG.md`.

## 4. Структура проекта (кратко)

```
universe/   канон        templates/  шаблоны      drafts/   идеи (не публикуются)
packages/   lore-schema · lore-parser · lore-validator · lore-indexer
scripts/lore.ts  CLI     src/  энциклопедия (Next.js)     docs/  документация и ADR
```

Подробности: [`ARCHITECTURE.md`](ARCHITECTURE.md). Не создавай пустых директорий и абстрактных модулей «на будущее». Архитектурные решения фиксируй в `docs/decisions/` (ADR).

## 5. Статусы сущностей (кратко)

`draft` → `proposed` → `review` → `canon`; `deprecated` (устарело, есть замена), `archived` (исторический материал), `unresolved` (известно, что есть, но суть требует уточнения). Полная семантика — в «Правилах канона».

## 6. Роли

Lore Architect · Worldbuilding Agent · Continuity Auditor · Science Research Agent · Art Director Agent · Software Engineer · Documentation Agent.
Зоны ответственности, входы/выходы и промпты-чеклисты: [`docs/agent-workflows/ROLES.md`](docs/agent-workflows/ROLES.md).

## 7. Код

- TypeScript strict, Zod для схем. Новые зависимости — только при реальной необходимости, без платных.
- Логика знаний — в `packages/*` без зависимости от Next.js/Obsidian. Приложения только читают.
- Новый тип сущности/связи → `packages/lore-schema` + шаблон + тест.
- Не требуй сервера для базовой работы; всё должно собираться статически.
- Секреты — только через `process.env`, не в репозитории.

## 8. Если не уверен

Остановись, зафиксируй вопрос в «Открытых вопросах» и продолжай с тем, что не требует догадок.
