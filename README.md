# Archon Universe Platform

Монорепозиторий научно-фантастической вселенной **«Архон» (Archon)**: база знаний, инструменты проверки канона, сайт-энциклопедия, инфраструктура для AI-агентов и (в будущем) игр.

> **Один источник знаний — множество способов его использования.**
> Источник истины — Markdown + YAML в [`universe/`](universe/). Всё остальное — производные.

Статус: Этапы **Foundation** и **Knowledge Base MVP** завершены, **Encyclopedia MVP** запущен. Подробности — [`ROADMAP.md`](ROADMAP.md), аудит — [`PROJECT_AUDIT.md`](PROJECT_AUDIT.md).

## Быстрый старт

Требуется Node.js ≥ 20.11 и npm; для разработки и CI используется Node.js 22 (см. `.nvmrc`).

```bash
npm install

# База знаний
npx tsx scripts/lore.ts validate      # полная проверка (0 ошибок = ок)
npx tsx scripts/lore.ts build         # validate + index + graph + report → build/lore/
npm test                              # модульные тесты
npm run test:e2e                      # Playwright + @sparticuz/chromium, desktop и mobile

# Энциклопедия (читает universe/ напрямую)
npm run dev                           # http://localhost:3000
npm run build && npm run start
```

Браузерные проверки собирают production-версию и автоматически поднимают отдельный сервер на порту 3100. `npm run test:e2e:dev` дополнительно проверяет стили в dev-режиме на порту 3200. Dev-сервер использует webpack и polling файлов, чтобы изменения CSS не терялись в средах с ненадёжными событиями файловой системы; в таком режиме обновления могут приходить с небольшой задержкой. В Linux используются Chromium и библиотеки из `@sparticuz/chromium`; нужен `tar`. Для другого установленного браузера задайте `CHROMIUM_EXECUTABLE_PATH`. Визуальные эталоны снимков хранятся в `e2e/`; обновлять их командой `npm run test:e2e -- --update-snapshots` только после визуальной проверки. Снимки могут зависеть от платформы.

Аудит зависимостей: `npm audit --omit=dev` проверяет production-цепочку. Полный `npm audit` также сообщает о разработческой цепочке `drizzle-kit` → `@esbuild-kit` → уязвимый esbuild (GHSA-67mh-4wv8-2f99, касается dev-сервера esbuild). Автоматическое исправление npm предлагает несовместимое понижение `drizzle-kit`; не применяйте `npm audit fix --force` без отдельной проверки инструментов и миграций.

Команды CLI (`scripts/lore.ts`): `validate` · `index` · `graph` · `check-links` · `report` · `build`.
Выходные файлы: `build/lore/{index,graph,timeline,diagnostics}.json`, `build/lore/contradictions.md`; реестр сущностей обновляется в `universe/00-meta/Реестр сущностей.md` (команда `index`).

> Страницы энциклопедии формируются из файлов при сборке, но проект пока не настроен как статический экспорт: динамический `/api/health` использует PostgreSQL и `DATABASE_URL`. Перед деплоем выберите режим хостинга и проверьте доступность `universe/` в окружении сборки и сервера. Для проверки endpoint нужна работающая БД.
>
> Полный реестр сущностей доступен в репозитории, но не публикуется на сайте: он включает также `draft` и `archived`. Остальные мета-заметки публикуются целиком — не помещайте в них приватные данные.
>
> Сайт показывает гипотезы (`/hypotheses`), рабочие концепции из `drafts/concepts/` и концепт-арт (`/concept-art`) как неканонические материалы. Все Markdown-файлы в `drafts/concepts/` публичны: личные и закрытые заметки храните в других подпапках `drafts/`. Промпты и метаданные изображений — в `assets/concept-art/catalog.json`.

## Obsidian

Откройте **корень репозитория** как Vault (*Open folder as vault*). Платные и сторонние плагины не нужны. Стартовая точка — [`universe/00-meta/Вселенная Архон.md`](universe/00-meta/Вселенная%20Архон.md). Шаблоны — `templates/` (core-плагин *Templates* уже настроен). Контент не зависит от Obsidian: это обычный Markdown, вики-ссылки `[[Название]]` разбираются и самим проектом.

## Как добавить сущность

1. Убедитесь, что такой сущности ещё нет (поиск по `id`/`title`/`aliases`).
2. Скопируйте шаблон из `templates/` в нужную папку `universe/NN-…/` (в Obsidian: *Insert template*), назовите файл русским названием: `Название Сущности.md`.
3. Заполните `id` (постоянный, `тип-kebab-case`), `title`, `type`, `status` (новые — не выше `review`), даты.
4. Пишите только известное; неизвестное — в «Противоречия и неизвестные сведения».
5. `npx tsx scripts/lore.ts validate` → PR. Подробно: [`docs/worldbuilding/ENTITY-GUIDE.md`](docs/worldbuilding/ENTITY-GUIDE.md).

### Личные черновики решений

На странице гипотезы можно сохранить оценку и оговорки в localStorage текущего браузера. На странице гипотез доступен список и текст для копирования; обязательные зависимости без оценки или с отрицательной оценкой подсвечиваются. Если обе явно несовместимые гипотезы отмечены «нравится», появляется предупреждение с просьбой проверить условия и оговорки; оно не меняет оценки. Черновики не меняют реестр и не утверждают канон, не синхронизируются и могут исчезнуть при очистке данных браузера. При повреждённом формате приложение не перезаписывает сохранённые данные. При изменении того же ответа в другой вкладке несохранённый ввод остаётся в форме: можно загрузить чужую версию или явно перезаписать её своей. Ввод, который ещё не сохранён, будет потерян при перезагрузке или уходе со страницы. При обычном переходе по внутренней ссылке показывается подтверждение; при перезагрузке и закрытии вкладки браузер может показать собственное предупреждение. Оно зависит от браузера и не гарантировано, особенно на мобильных устройствах; переходы по истории приложения тоже могут не предупредить. Сохраняйте ответ до ухода со страницы.

Карта гипотез различает упоминания, направленные обязательные зависимости и явно отмеченные несовместимые варианты. Несовместимость может действовать только при условиях, указанных в самих гипотезах; карта не заменяет их текста и не утверждает канон.

В мастерской гипотез быстрые ссылки ведут к каталогу, личным черновикам и карте. Каталог фильтрует по ID, названию, краткому описанию и статусу реестра; это не фильтр личных оценок и не полнотекстовый поиск. При пустых фильтрах отображается весь реестр.

Раздел «Вселенная» — читательский путеводитель по опубликованным записям; прежние принципы и справочные материалы доступны в `/universe/reference`. Профиль персонажа с привязанным изображением показывает его рядом с введением, сохраняя статус визуального исследования и ссылку на происхождение и промпт.

Карта гипотез в мастерской — интерактивная сеть: узлы и поле можно перетаскивать, масштабировать и вписывать в экран. Флажки скрывают только линии выбранного типа; список связей выбранной гипотезы по-прежнему показывает все типы и оба направления. Список узлов доступен с клавиатуры. Упоминание ID не означает зависимости или принятия решения; карта не является графом утверждённого лора.

В панели карты можно выбрать связанную гипотезу, не покидая сеть, и вернуться к предыдущему выбору; отдельная ссылка открывает полную запись. Поиск подсвечивает совпадающие узлы, когда выбор сброшен; при выборе приоритет отдаётся его непосредственным связям.
