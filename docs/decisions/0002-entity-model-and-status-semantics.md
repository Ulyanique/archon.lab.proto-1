# ADR-0002 — Модель сущностей, ID и семантика статусов

- Статус: принято
- Дата: 2026-11-18

## Решения

1. **Сущность = файл `.md` + YAML frontmatter** в `universe/` (кроме `00-meta/`, где лежат справочные заметки без обязательного frontmatter).
2. **ID** — `<префикс>-<kebab-case>`, постоянный, не зависит от имени файла. Префикс обязан соответствовать типу. Исключение (C-7): тип `ai` допускает префикс `character-`, т.к. ТЗ §9.5 так называет `character-eleon`, `character-eleonora`.
3. **Схема строгая** (`.strict()`): неизвестные поля — ошибка, чтобы опечатки (`relatd:`) не терялись. Новое поле добавляется в `lore-schema`.
4. **Статусы** (7) имеют машинную семантику в `STATUS_INFO`: `published` (виден ли на сайте) и `canonical`. Публикуются все, кроме `draft` и `archived`. Не-канонические публикуются с видимой пометкой (штамп статуса и уведомление).
5. **Канон не присваивается автоматически.** Миграция ТЗ даёт `review`/`unresolved`.
6. **Типизированные связи** берутся из `related` (общая), `relations` (тип + цель + примечание), полей событий и вики-ссылок (`mention`). Реестр типов — `RELATION_TYPES`, расширяемый; незарегистрированный тип — предупреждение.
7. **Научный статус** — отдельное поле `science_status` у технологий (ТЗ §5).
8. **Хронология** — события со структурным блоком `date` (`precision`, `calendar`, `certainty`, `start`, `end`) и частичным порядком `after`. Глобальный порядок не вычисляется.
9. **Именование файлов** — по названию сущности (кириллица допустима); валидатор предупреждает, если имя файла ≠ `title`.

## Отвергнутые варианты

- ID = имя файла: ломается при переименовании.
- Один файл — много сущностей: сложнее ссылки и diff.
- Свободная схема (`passthrough`): скрывает ошибки.

## Последствия

Изменение набора типов/статусов/полей — только через `packages/lore-schema` вместе с тестами, шаблонами и документацией (`docs/architecture/knowledge-base.md`).
