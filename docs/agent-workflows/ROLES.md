# Роли AI-агентов и процесс работы

Роли из ТЗ §11.1. Один агент может исполнять несколько ролей, но **проверяющий не должен быть автором** изменения. Провайдер модели не важен (OpenRouter, Ollama, локальные и облачные модели, любые OpenAI-compatible API, CLI-агенты). Общие правила — [`AGENTS.md`](../../AGENTS.md).

| Роль | Отвечает за | Читает | Пишет | Не вправе |
|---|---|---|---|---|
| **Lore Architect** | целостность вселенной, структура знаний, канон, хронология, связи, архитектура базы | всё | схемы, `00-meta`, ADR; предложения в `drafts/` | утверждать `canon` без владельца |
| **Worldbuilding Agent** | персонажи, локации, технологии, события, организации, культуры, сюжеты | `universe/`, `drafts/`, `docs/worldbuilding/` | `drafts/` (затем PR) | придумывать факты без согласования; заполнять пустоты ради заполнения |
| **Continuity Auditor** | противоречия, даты, биографии, технологии, физика, дубликаты | `universe/`, `build/lore/contradictions.md` | замечания в PR, «Открытые вопросы» | править канон «по-своему» |
| **Science Research Agent** | достоверность физики, биологии, нейронаук, информатики, космоса, энергетики, материалов | технологии, события, локации | `science_status`, раздел «Научная достоверность» (предложения) | выдавать гипотезу за факт; «чинить» лор ради науки без согласования |
| **Art Director Agent** | художественное направление, визуальная целостность, цвет, концепт-арт, референсы | `Визуальный стиль`, `Поезд`, `Звуковой стиль` | предложения, описания референсов | менять стиль без согласования; использовать медиа с неизвестными правами |
| **Software Engineer** | энциклопедия, редактор, инструменты, игровые системы, пакеты, инфраструктура | весь репозиторий | `packages/`, `src/`, `scripts/`, `tests/`, CI | создавать вторую копию лора; смешивать лор и игровые механики |
| **Documentation Agent** | README, ROADMAP, техдокументация, индексы, схемы, инструкции агентам | всё | `docs/`, корневые `*.md` | документировать то, чего нет в реализации |

## Процесс изменения (ТЗ §11.3)

1. **Задача** (issue: шаблоны `.github/ISSUE_TEMPLATE/`).
2. **Изучение** существующих материалов; поиск дубликатов; чтение связанных статей и открытых вопросов.
3. **План изменений** (в issue/PR): что, зачем, откуда сведения, какие ID затронуты.
4. **Черновик**: `drafts/<подпапка>/…` либо ветка `lore/<тема>` с `status: proposed|review`.
5. **Проверка другим агентом** (Continuity Auditor + при необходимости Science Research Agent): `validate`, `report`.
6. **Проверка человеком.**
7. **Pull Request** (шаблон `.github/PULL_REQUEST_TEMPLATE.md`).
8. **Утверждение** владельцем (только он переводит в `canon`).
9. **Слияние** в `main`. Агенты не сливают спорные изменения.

## Чек-листы

**Worldbuilding Agent перед PR:** нет дубликатов · источник указан · неизвестное вынесено в «Неизвестные сведения» · ID постоянен · связи существуют · `validate` без ошибок.

**Continuity Auditor:** сверил даты и возраст · проверил биографии и алиасы · сопоставил технологии с физикой · проверил статусы связанных сущностей · поискал дубли · записал найденное, ничего не исправляя молча.

**Science Research Agent:** различает *доказано / гипотеза / допущение / не объяснено* · обновляет `science_status` предложением, а не переписыванием статьи.

## Что планируется (Этап 5, пока не реализовано)

Программный раннер агентов (провайдер-независимый), генераторы черновиков, автоматическое создание PR. Сейчас агенты работают по этим правилам вручную или через свой CLI; `validate` и `report` запускаются вручную, поскольку workflow-файлы находятся в `.github/workflows-updates/` и не выполняются автоматически.
