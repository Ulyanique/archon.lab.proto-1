# Руководство: как создавать и менять сущности

Дополняет [`Правила канона`](../../universe/00-meta/Правила%20канона.md) и [`AGENTS.md`](../../AGENTS.md).

## Создание новой сущности

1. **Поиск дубликатов.** Проверьте `id`, `title`, `aliases`: `grep -ri "<имя>" universe drafts` или `build/lore/index.json`. Валидатор тоже ловит совпадения имён (`NAME-DUP`).
2. **Источник.** Откуда сведения? ТЗ, ваше решение (укажите дату и контекст), черновик из `drafts/`. Нет источника — нет сущности.
3. **Шаблон.** Скопируйте из `templates/` (Character, AI, Location, Technology, Event, Organization, Faction, Artifact, Story, Concept). В Obsidian: *Insert template*.
4. **Папка** по типу: персонаж/ИИ → `04-characters`, локация → `03-locations`, технология → `07-technology`, событие → `08-events`, концепция → `01-cosmology`, организация → `06-organizations`, фракция → `05-factions`, артефакт → `09-artifacts`, культура → `10-cultures`, религия → `11-religions`, история/документ → `12-stories`. Нужной папки нет — создайте её вместе с первой статьёй.
5. **Имя файла** — название сущности по-русски: `Алексей Харпер.md`. Совпадает с `title`.
6. **ID** — `тип-kebab-case`, латиница: `character-alexei-harper`. Не меняется никогда.
7. **Статус.** Новые сущности — `draft` (не публикуются), `proposed` или `review`. **`canon` ставит владелец.**
8. **Содержание.** Только установленное. Пустой раздел — `—`. Неизвестное и сомнительное — в «Противоречия и неизвестные сведения». Гипотезы маркируйте словами «предположительно/возможно».
9. **Связи.** `related` — общие; `relations` — с типом (`type`, `target`, `note`); в тексте — `[[Вики-ссылки]]`. Все ID должны существовать.
10. **Проверка:** `npx tsx scripts/lore.ts validate`, затем `report`; `npx tsx scripts/lore.ts index` обновит реестр.
11. **PR** (см. [`CONTRIBUTING.md`](../../CONTRIBUTING.md)).

## Событие и хронология

- Даты не придумывайте. Не знаете — `date.precision: unknown`.
- Порядок событий задаётся только полем `after` (ID событий, которые были раньше). Не задавайте порядок «по ощущениям».
- `date.certainty`: `confirmed | estimated | disputed | unknown`.
- Для `calendar: gregorian` формат проверяется; для `in-universe`/`unspecified` — нет (календарь вселенной не определён, Q-9).

## Технология

- `science_status`: `real` (существует), `theoretical` (возможна теоретически), `fictional-assumption` (допущение), `unexplained` (принципиально не объяснена в каноне), `unassessed` (не проверялась).
- Магия и произвольные нарушения физики запрещены; необъяснимое помечайте `unexplained`.

## Изменение существующей статьи

- Локальная правка, а не переписывание. Не удаляйте — `deprecated` + `superseded_by`.
- `updated` — сегодняшняя дата. `created` и `id` не трогать.
- Меняется утверждённый (`canon`) факт — только с явного разрешения владельца; зафиксируйте в `CHANGELOG.md`.
- Нашли противоречие — не «исправляйте» молча: запишите его в статью и в [`Открытые вопросы`](../../universe/00-meta/Открытые%20вопросы.md).

## Переименование и удаление

- Переименование файла — только `git mv`/переименование в Obsidian (ссылки обновятся); ID сохраняется.
- Удаление — только по согласованию; вместо него `archived`.
